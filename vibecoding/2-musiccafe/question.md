# 02 · 各端功能清单（v1.1 · 已冻结 2026-09-06）

> 状态：草案 · 优先级：**P0 = MVP 必须** / P1 = 第二迭代 / P2 = 远期（仅预留）
> 范围决策（已确认，见决策日志 D7-D12）：单店；奶茶店取餐模式（无桌码、取餐号叫号）；永久不做外卖；**点单机=顾客自助 kiosk（麦当劳自助机式，无店员登录）**；代客点单/叫号/退改单/交接班在商家端；点歌三层权益；曲库自有上传；支付 mock 起步。

## 一、顾客端（Taro 一码多端：微信小程序 / H5 / Android 点单机）

> 三个形态共享同一份功能与代码（条件编译裁剪），**仅 1.2 所列细节有差异**。

### 1.1 共用功能清单
| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 店铺信息与公告 | 店名/Logo/营业状态与时段/打烊文案；公告多条 NoticeBar 轮播（`shop/info`） |
| P0 | 菜单浏览 | 分类导航 + 商品列表、售罄/下架态、商品图片 |

### 1.2 端形态差异（仅此不同）
| 差异点 | 微信小程序 | H5（店内扫码） | Android 点单机（kiosk） |
|---|---|---|---|
| 定位 | 线上预点自取 | 店内扫码点单 | 店内自助点单（顾客自己操作店里的机器） |
| 登录 | 微信一键（手机号选填） | 游客模式（手机号选填） | 顾客免登录；**设备绑定识别**（首次部署时店员输管理码绑定一次，之后开机自动进自助模式；退出/维护需店员 PIN 防顾客乱动） |
| 支付 | 小程序内支付（JSAPI） | 跳转微信支付 | **弹出预支付二维码，顾客自己扫码付**（Native 模式） |
| 交互形态 | 手机竖屏 | 手机竖屏 | 大按钮/大字号；常驻自助模式（超时自动回首页）、取餐号大字展示 |
| 小票 | — | — | P1 本地小票打印（Android 原生接入，形态见开放细节 7） |

## 二、商家端·管理面板（Web · antd）

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 接单制作工作台 | 管理面板详细版，店员制作饮品用：新单实时提醒（声音+角标，WS）、订单流转（接单→制作中→待取→已完成/取消/退款）、待取列表与"已取餐"确认、今日订单看板 |
| P0 | **取餐叫号大屏** | 奶茶店式投屏页：大字号滚动展示"正在制作的号码 / 可取餐的号码"，已取餐自动移除；浏览器全屏打开即用（电视盒子/PC 均可），与播放屏各自独立投屏 |
| P0 | 代客点单 | 柜台场景：店员在商家端代顾客下单，收款方式标记（现金/顾客扫码/其他） |
| P0 | 播放台（店内播放端） | HTML5 audio 播放器、当前播放/队列管理（置顶/删除/跳过）、播完自动取队首、**兜底自动切歌**、播放历史 |
| P0 | 商品管理 | 分类 CRUD、商品 CRUD（图/描述/价格/制作时长）、**规格模板管理**（门店级模板，商品引用）、上下架/售罄 |
| P0 | 曲库管理 | 音频上传（对象存储）、歌名/歌手/标签/封面维护、试听、上下架、占用空间统计 |
| P0 | 店员与角色管理 | 店长/店员账号（商家端登录）、操作权限（代客点单/退款/叫号/播放台/系统配置分别授权） |
| P0 | 店铺管理 | 营业开关与时段、取餐号规则；含点单机设备管理（绑定码生成/设备列表与在线状态/解绑停用，P1 子项） |
| P1 | 退单/改单 | 撤销未制作订单、修改备注/加项（细则在 API 设计定） |
| P1 | 数据统计 | 日/周销量、热销商品、点歌榜、时段分析（ECharts）；**含交接班统计**（按班次汇总单数/金额/收款方式占比） |
| P1 | **系统配置**（统一配置中心） | **支付管理**（mock→微信 V3 切换、退款操作、对账流水）；**点歌规则**（每日免费上限/赠权发放规则/付费定价/点歌开关）；通知提醒（新单声音与语音播报）；打印设置（打印机绑定、自动打印开关）；播放台行为（空闲自动随机播放、音量）；操作日志审计；修改密码 |
| P1 | 小票打印 | 优先云打印机（芯烨云等，HTTP API 零原生）；若需点单机本地打印（USB/蓝牙），点单机 Android 端原生接入（Taro RN 原生模块或 WebView 壳桥接，形态见开放细节 7） |
| P2 | 多门店演进 | **预留扩展能力**：业务表带 `shop_id`（默认 1）、模块边界清晰；不建三级体系、不做界面 |

## 三、后端能力

| 优先级 | 能力 | 说明 |
|---|---|---|
| P0 | REST 版本化双 API 面 | `/api/v1/app/**`（顾客端+点单机）与 `/api/v1/admin/**`（商家端/叫号大屏/播放台）；**版本段**（v1）支持破坏性演进时可 v2 并存，**受众段**（app/admin）用于鉴权域隔离：两套 JWT 策略、限流与审计按面独立配置 |
| P2 | 请求加密与防重放 | **混合加密**：客户端生成随机 AES 密钥加密请求体，再用服务端 RSA 公钥加密该 AES 密钥（非对称只包密钥——纯 RSA 加密整包受密钥长度限制且性能不可行）；**防重放三件套**：timestamp（±5 分钟窗口）+ nonce（Redis SETNX 幂等去重）+ 二者纳入签名不可剥离；公钥支持轮换（keyId 版本字段）；覆盖敏感写接口（登录/下单/支付/点歌），只读查询豁免；开发环境可配置关闭 |
| P0 | WebSocket 三通道 | ①顾客队列广播（当前播放/队列/取餐叫号）②店员工作台（新单提醒）③播放端（播放指令/确认） |
| P0 | 订单域 | 状态机（待支付→已支付→制作中→待取→完成/取消/退款）、**取餐号：Redis INCR 按日原子发号（支付成功后发放，未付不占号；跳号可接受）**、Redis 故障用"当日最大号"MySQL 回填 + 唯一索引兜底、超时未支付自动取消、金额服务端重算、明细快照 |
| P0 | 点歌队列引擎 | 三层优先级（付费点歌次数/付费 > 免费 FIFO）、每日配额记账、点歌状态机（待播→播放中→已播/已跳过）、播完推进与兜底、队列变更广播 |
| P0 | 支付抽象（三模式） | mock 实现 + 微信 V3 适配位：JSAPI（小程序内）/ H5 支付（跳转微信）/ Native（点单机生成二维码，顾客扫码付） |
| P0 | 文件上传 | 音频/图片 → StorageAdapter（local 本地磁盘默认、s3 预留，**不引入 MinIO**） |
| P1 | 微信支付 V3 | 统一下单/回调/退款，回调幂等（商户号到位后启用） |
| P1 | 定时统计任务 | 日结快照，热销/点歌榜聚合 |
| P1 | 云打印推送 | 芯烨云等 HTTP API：支付成功/接单后自动或手动打印小票（零原生依赖，与点单机本地打印可并存） |

## 四、明确不做（写死边界）

- **外卖配送**（永久）
- **桌码堂食**（仅 DB 预留 `table_id` 等字段，无任何界面与接口）
- **多租户/连锁**（仅预留演进空间）
- **任何盗链/聚合音源**（版权红线）
